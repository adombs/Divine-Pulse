# Fallback inventory and stale-test audit

## Changes accompanying this inventory

This inventory records the **baseline** behaviors at `5fd7c60`, not a claim that every substitute remains after this
work. Source line numbers refer to that baseline. The History and Battalion refinements are in PRs #74 and #73;
required-asset frontend handling and required-data backend handling (PR #75) are separate changes linked to issue #72.

- Removed visual substitutes: arbitrary `GameImage`/`PortraitImage` fallback props, portrait initials, requested
  sprite to generic sprite/portrait/weapon badge chains, generic spell/item/affiliation substitute icons, alternate
  sprite-look substitution, the favicon-on-failure substitution, and reconstructed terrain as a missing native-map
  replacement. The Battalion change removes drawn replacement grid/cells/badges/chevrons.
- Required image failures now show explicit missing-asset text and/or a game-file issue with the requested path.
  Failed imported JSON and selected-language text are reported. Reference/support loaders no longer turn failure
  into a successful empty reference; malformed required Battalion endurance no longer becomes zero.
- The backend change makes required JSON/table/text reads in an existing import raise `GameAssetError`, translated
  to a structured 503 response. A missing import remains a first-run sentinel; valid optional DLC and empty
  categories remain valid. Missing selected languages never silently switch to English or another language.
- Kept deliberate native selection: aliases declared by the game/import, shared class bodies, genuinely generic
  heads, characters with no alternate portrait, spoiler concealment and explicit Appearance choices. These select
  the requested representation; they do not recover from a missing required file by drawing something else.
- Other compatibility, inference, preference and platform mechanisms below are **listed for review**, not removed
  indiscriminately. In particular, inferred combat logging, old-record support and backup recovery change product
  behavior if removed. Further candidates include fabricated finish timestamps, failed roster/history reads
  becoming empty collections, and ambiguous scenario chapter guesses.

The complete audit identified **73 mechanisms**: 32 asset/reference mechanisms, 19 history/inference mechanisms,
and 22 transport/recovery/platform mechanisms. It is grouped by behavior rather than every default-valued field.

Audit date: 2026-11-06. Baseline: release/1.3.0 commit `5fd7c60` (PR69 merged). Read-only investigation; no source edits or git mutations. Root and UI workers are changing files concurrently, so line numbers below refer to that baseline and can shift.

This is a behavioral inventory, grouped by mechanism rather than listing every `??`, `.get`, default dataclass field, or null check. It covers the first-party runtime under `frontend/src`, `backend/app`, `tools`, and `packaging`. Search captured 795 candidate fallback/exception/default lines in `C:/Users/asent/.agents/evidence/fallback-search.txt`; a Python AST index of every exception handler is in `fallback-exceptions.txt`. Mechanism owners and their important callers were inspected. This is not a proof that arbitrary application code can never recover/substitute: no runtime fault injection or third-party implementation audit was performed. Dependencies, generated build output, game dump and image bytes were excluded.

## Decision vocabulary

- **Replace**: silent substitution masks a missing required asset/reference or failure; use a typed error or explicit missing/unavailable sentinel with context.
- **Review**: real compatibility/inference behavior; remove only after declaring old formats unsupported or proving the inference unnecessary.
- **Keep**: ordinary initial values, intentional native selection, or explicit unknown/recovery state. These do not pretend missing evidence is a real value.
